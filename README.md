# Research Task 08: LLM Bias Detection in Data Narratives

## Overview
This project is a controlled experiment to detect systematic biases in LLM-generated data narratives. The study tests whether small variations in prompt framing, proxy/structural context, or confirmation priming change interpretations of identical team-level football statistics. The work builds on earlier sports narrative and ethics tasks.

---

## Experimental Design (Phase 1)
- Dataset: Premier League team-level match statistics used previously; raw data is not included in this repository per instructions.
- Anonymization: All real team names are mapped to anonymous identifiers (e.g., Team Alpha, Team Rho). A missed mapping (“Brentford”) was fixed to Team Phi. The sanitized file is not committed; notebooks/scripts document how to regenerate it from authorized data.

### Hypotheses and Conditions
- H1 Framing effects: Negative (“failures”) vs. Positive (“potential”).
- H2 Proxy/structural bias: Neutral context vs. Low market status context.
- H3 Confirmation/selection bias: Neutral question vs. Primed with a secondary conclusion (e.g., “defense was the key factor”).

### Prompt Set
Six minimally different prompts (3 hypotheses × 2 conditions) embed identical sanitized statistics within each pair. The prompt list and generation logic are provided via the prompt file and the design notebook.

## Analysis Plan (Phase 3)
- Quantitative:
  - Sentiment scoring per response; compare distributions across conditions.
  - Recommendation taxonomy counts (defensive vs. offensive, individual vs. team).
  - Significance checks (e.g., chi‑square on category frequencies) to triage effect sizes.
- Qualitative:
  - Language patterns, cherry‑picking, and alignment with framing/priming.
  - Fabrication checks (claims not supported by provided stats).
- Validation:
  - Programmatic verification of cited claims against sanitized match statistics; contradictions flagged for the bias catalogue.

## Reproduction (Manual)
1) Open prompts/all_prompts.* and select a hypothesis/condition prompt.
2) Prepend the corresponding sanitized match snippet (locally generated) to the prompt.
3) Run twice:
   - First in Claude 4.5; record output as Sample 1.
   - Second in GPT‑5; record output as Sample 2.
4) Paste outputs into results/results.xlsx under the matching row and proceed to analysis.

Note: The raw dataset is not included. The sanitized dataset is also not committed; anonymization and selection logic are documented so it can be regenerated by authorized users.
